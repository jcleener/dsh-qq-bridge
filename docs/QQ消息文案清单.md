## 1. 消息范围与开关

| 类别 | 内容来源 | 控制/触发 |
|---|---|---|
| 指令回执 | 插件固定模板 | 用户输入指令后回复 |
| 最终结果 | 模型生成文本 | QQ 回复观察器在轮次结束后发送；不发送 reasoning 内容块 |
| 待办清单 | todo/write | pushTodo；相同清单去重 |
| 交付清单 | deliverables/presented | pushDeliverable；只列文件，不自动发送文件本体 |
| 工具调用 | tool/call | pushToolCall；跳过 todo_write、present 的专门过程行 |
| 过程旁白 | 同时有 text 和 tool-call 的 assistant/message | pushNarration |
| 会话状态 | 完成、待审批、待问答 | notifyOnComplete；只推主会话；不通知正接入该会话的用户 |
| 主动文字/文件 | qq_send、qq_send_file 工具 | Agent 显式调用；不是最终回复模板 |
| 定时消息 | qq_schedule | 固定文本或到点执行 prompt |
| QQ 输入状态 | msg_type=6 | 非文字消息，每5秒续发 |

`/断开` 对该 QQ 用户暂停自动推送、结果、文件与输入状态，清空会话绑定；指令的直接回执仍发送。普通消息不重新建会话，须 `/会话 <ID>` 或 `/new` 重新接入。已发出的 QQ 消息不可撤回。

## 5. 主动发文字与文件

- `qq_send`：QQ收到 Agent 提供的 `{text}`，trim 后最多2000字，超出加 `…`，无固定前缀。
- `qq_send_file`：发送 QQ 原生图片/视频/音频或文件卡片，不是仅文字；最多5文件，每文件200MB。
- 交付清单不会自动调用文件发送。

以下是工具回报（先回给 Agent，可能被模型转述到QQ），**不是直接额外向QQ发送的固定气泡**：

| ID | 当前回报 |
|---|---|
| TOOL-01 | `已发往 QQ（{字数} 字，{收件人来源}）：{最多60字预览}` |
| TOOL-02 | `发往 QQ（{收件人来源}）：\n{文件逐条结果}` |
| TOOL-03 | 文件成功 `✓ {文件名}（{KB}KB）` |
| TOOL-04 | 非文件 `✗ {路径}：不是普通文件` |
| TOOL-05 | 过大 `✗ {文件名}：{MB}MB 超过 QQ 硬限 200MB（文件仍在电脑上：{完整路径}）` |
| TOOL-06 | 文件异常 `✗ {路径末三段}：{错误}` |
| TOOL-07 | 排定任务 `已排定：{定时任务行}` |

优化需考虑完整路径是否需要暴露到手机、工具参数是否可能含敏感内容。

频率：`一次 +{N}min` / `工作日 {HH:MM}` / `一次 {HH:MM}` / `每天 {HH:MM}`。

执行位置：`🆕无头会话` / `📍当前会话`。断开会暂停发送，不会删除已排定任务；prompt任务仍可在桌面执行。

## 7. 文本排版与非QQ可见内容

- 最终回复与模板统一经 sendText；检测Markdown时尝试 msg_type=2，失败退为纯文本，再失败按片二分。
- 分片只有首片带被动回复msg_id；重复事件按入站消息ID去重。
- “正在输入”是QQ状态，非可改的文案气泡。
- 图片下载/文件上传/重连/路由/锁/registry等本机日志不计入QQ文案；技术错误若被外层catch转成 `❌ {错误}` 才可能成为用户可见文字。
- 网页设置标签、后台启动器窗口文案不属于本清单的QQ消息范围。
