# QQ Bridge 文案优化讨论稿（不修改行为）

请配合 `QQ消息文案清单.md` 审阅。下面不是已实施的改动，而是下一步可选方案。

## 优先消除误导

1. `/帮助` 的“只回复最终结果，思考过程与工具调用不展示”与已存在的待办/交付/工具/旁白开关不一致。可以改为“默认转发会话结果；过程消息可在设置中选择。不会发送模型思考内容。”
2. `/模型` 无绑定、`/权限` 无绑定等提示仍推荐普通消息自动新建。`/断开` 后这不成立；建议统一为“当前未接入会话。用 /会话 <ID> 接入，或 /new 新建。”
3. 超时提示承诺“完成后会自动补发正文”，但观察器连续两次超时会退出。建议“任务可能仍在运行。可在桌面查看进度；桥接会继续等待一段时间。”
4. `/stop` 的命令回执和回复观察器的停止报告可能先后出现，容易形成重复反馈。讨论是保留详细结果、简化回执，还是抑制其中一条（后者涉及逻辑，不只是文案）。
5. `/断开` 的“所有会话推送暂停”包括现有定时任务消息和主动发送工具；任务并未删除。可明确“会话保留，QQ推送暂停；桌面继续运行”。

## 建议统一文案结构

- 成功：`✅ {动作完成}`；下一步另起一行，不把流程解释挤进一句。
- 需要用户操作：`{当前状态}\n{下一步指令}`。
- 参数错误：`❌ {具体问题}\n用法：{合法示例}`。
- 系统失败：`⚠️ {用户可理解的失败}\n{恢复办法}`；技术诊断默认放日志，不把长堆栈塞到手机。
- 可使用“未接入 / 已接入 / 已断开”三个固定词，不混用“附着 / 唤起 / 当前会话 / 无头”。
- 工作区、会话和模型清单统一编号与选择提示；返回/取消统一 `0`（需检查每个选择流程实际支持）。

## 过程消息降噪（涉及产品策略）

- 待办：是否每次变化都发整个15项清单？可选只发“已完成x/y · 当前事项”，完整清单按需查看。
- 工具调用：目前120字原始参数可能包含路径/脚本/敏感信息。优先显示工具description或用户可读动作，原始参数仅调试模式。
- 交付：是否隐藏完整/半完整路径，显示文件名和短说明？文件本体仍需显式请求。
- 旁白：保留对用户有价值的进展，避免“我来查看/让我再查”高频刷屏；这可能需要合并/限频规则。
- 完成通知：绑定其它会话时仍可能收到所有主会话完成广播。可讨论只通知QQ发起/订阅的会话，不影响桌面独立会话。
- 格式：正常最终回复保留Markdown，但桥接系统消息可以统一纯文本简洁风格。

## 请你选方向

A. 只改文案：不改变消息数量、受众和触发时机。
B. 文案 + 降噪：过程推送合并、去重复、缩短列表。
C. 文案 + 路由：限定哪些会话允许发到QQ，支持按会话订阅。

建议先 A，确认术语/风格，再单独做 B 或 C。给每个模板一个稳定ID，后续用“ID → 新文案”表批量替换，避免边讨论边改执行逻辑。
