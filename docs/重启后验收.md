## 为什么需要重启

- 待生效的改动只有 **`lib/index.js`**（Host 半）：
  「每轮结束按会话绑定把**最终正文**回 QQ」——修的就是"只收到中间回复（旁白/工具行），收不到正文"。
- 该文件 mtime 晚于当前宿主进程启动时间，所以运行中的仍是旧闭包；刷新页面/热更都不生效。
- `lib/messages.js`（`/提醒` 的官方目录 + `←当前` 标记）在上一次重启时已加载，**已经是新的**。

## 怎么重启（都不经过会话审批）

1. **在 QQ 里发 `/restart`**（桥接命令 → 实例管理器 `requestRestart`）；
2. 或**点桌面端的「重启实例」按钮**。

> 注意：Agent 工具 `dsh_restart` 走**会话审批**；当前桌面会话没有可用应答者，`ask` 策略下会
> fail-closed 直接 `rejected`。要恢复这条路，需把重启授权接到 QQ（与审批/问答同通路）——尚未做。

## 验收步骤

前置：确认 QQ 用户当前绑定的会话（短 ID）与你发消息的会话是同一个。可用 `/状态`、`/会话` 查看。

1. **正文回 QQ（本次主修复）**
   在 **QQ 绑定会话**里，从**桌面端**发一句需要动工具的话，例如「查一下广州明天的天气」。
   预期：QQ 依次收到 `💬`/`🔧` 中间行 **以及最终正文**（修复前只有中间行）。

2. **不重复**
   再**从 QQ** 发一句同样的话。
   预期：正文只出现 **一次**（由回复观察器发；轮末转发发现观察器在，会让位）。

3. **计划任务投递**
   在 QQ 里说「1 分钟后提醒我喝水」。
   预期：约 1 分钟后，QQ 收到该轮 **正文**；桌面原会话里也能看到这条提醒。

4. **`/提醒` 直接看官方目录**
   QQ 发 `/提醒`。
   预期：列出官方计划任务（全量，含已停止），每行形如
   `🕒 <8位ID> <标题> · <规则>（下次 月-日 时:分）[会话 <短ID> ←当前]（已停止）`，
   结尾两行是取消与新增提示。
   再发 `/提醒 删 <8位ID>` → 预期 `✅ 已取消计划任务 [...]（还剩 N 个）`。

5. **断开语义**
   QQ 发 `/断开`，然后在桌面端发一句话。
   预期：该轮正文不再推 QQ（实时推送与轮末转发都静音）；`/会话 <ID>` 重新接入后恢复。

6. **回归自检（可选，命令行）**
   ```bash
   node tests/qq-bridge/run-all.mjs                                        # 工作区副本
   node tests/qq-bridge/run-all.mjs ~/.dsh/profiles/desktop/plugins/dsh-qq-bridge   # 安装副本
   ```
   预期：两处都 `22/22 passed`。
